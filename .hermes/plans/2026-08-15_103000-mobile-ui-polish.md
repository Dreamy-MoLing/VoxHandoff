# 移动端 UI 对照原型逐项打磨计划

> 目标：移动端 UI 交互与视觉对齐冻结基线 `ui-prototype/`，真机验证达标后收尾提交。

**背景**：Codex 近两小时提交 `9a8fff1` 用 WebView 套壳原型 HTML，Linux 桌面/测试路径不生效、真机 `<script type="module">` 被 CORS 拦截，交互全断。已 `git revert` 暂存（未提交）。移动端恢复为原生 `NativeMobileHomeScreen` + SignalCoreView mobileVisual。

**流程**（舰长指示：和 Codex 沟通协作，对照原型逐项打磨，验证达标才收尾）：

1. 真机装当前 APK，用 uiautomator dump + 截图（压小）实拍四态（待机/文字/录音/连接）现状
2. 与 `ui-prototype/` 并排逐项对比，产出**结构性差异清单**（元素/布局/动效参数）
3. 写任务书（现状/目标/Phase/硬边界/报告 五段式，要求 Codex 读范本源码不看图）→ 启动 `codex exec`
4. 无人值守，`notify_on_complete=true` 收通知，不频繁 poll
5. 验收：真机截图与范本并排核对四态 + 独立跑 gate（`AGENT_TALK_FLUTTER_ROOT=/home/roco/develop/flutter-3.44.6 npm run flutter:check`）
6. 达标后收尾：确认中文 conventional commits、git status 干净、不 push 不触发 CI

**验证手段（快路径）**：
- 亚秒级原语：`adb shell uiautomator dump` + `dumpsys window | grep mCurrentFocus`
- 截图压小（PIL thumbnail ~585px）再喂视觉模型，不做实时时序判断
- 录音态只验证视觉（球心波形/文案），不录音不送 STT

**硬边界**：桌面 golden 零变化；`ui-prototype/` 只读不修改；生产代码无 setTimeout；不新增依赖（WebView 已回退）；不 push。
